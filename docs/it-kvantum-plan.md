# Что можно сделать для IT-квантума: удачная модель и линейка продуктов

> Опора — разбор удачного бесплатного браузерного симулятора электроники и робототехники.
> Его механика: схемный редактор + редактор кода + монитор порта + осциллограф + задания
> с автопроверкой + ИИ-ассистент + облако проектов. Без установки, без обязательной регистрации,
> на русском, работает на планшете.

---

## 1. Что на самом деле сделал удачный продукт (его «формула», а не тема)

1. **Узкая предметная область, оцифрованная целиком.** Один цикл, замкнутый в браузере: *собрал железо → написал код → запустил → увидел сигнал*. Не «лекции про Arduino», а среда.
2. **Ноль установки, ноль регистрации.** Регистрация только там, где она реально нужна (облако, ИИ, задания). Ученик открывает ссылку и через 10 секунд уже мигает светодиод.
3. **Приборы внутри.** Осциллограф, монитор порта, генератор сигналов — то, чего физически не хватает на 25 человек.
4. **Задания с автопроверкой + ИИ-ассистент.** Снимает с педагога ручную проверку и персональные «а почему у меня не работает».
5. **Язык и лексика школы.** Русский, 45-минутный урок, слабый ПК, планшет, ребёнок 10–17 лет.
6. **Облако проектов и шаринг ссылкой** — ученик продолжает дома с того же места.
7. **Открытость для ИИ-краулеров** (`llms.txt`, FAQ-разметка) — сейчас это реальный канал бесплатного трафика из нейросетей.

**Главный вывод:** это не сайт про конкретную плату. Это *тренажёр, который заменяет стенд там, где стенда не хватает*. Именно эту механику и надо переносить в IT-квантум.

---

## 2. Что в IT-квантуме болит ровно так же

| Боль | Следствие |
|---|---|
| Нет прав администратора — нельзя поставить Python, MySQL, VirtualBox, Packet Tracer | Половина программы «на бумаге» |
| ПК слабые / разные ОС (Windows, Alt Linux, Android-планшеты) | Методичка не воспроизводится |
| Дома среды нет | Домашние задания не делаются, мотивация падает |
| Первые 20 минут урока уходят на «почему pip не работает» | Потеря 1/3 занятия |
| 25 работ проверяются руками | Нет обратной связи в моменте, нет объективной оценки |
| Нет «песочницы безопасности» | Дети боятся что-то сломать, изучают поверхностно |

Значит аналог нужен не «курс по Python», а **браузерная среда + автопроверка + приборы/визуализация внутренних процессов**.

## 3. Варианты «по аналогии» — что конкретно можно сделать

Оценка: **S** — 1–3 недели одному разработчику, **M** — 1–2 месяца, **L** — 3+ месяца / команда.

### 3.1. Python-класс в браузере («IT-квантум.рф», самое близкое к эталону)
- **Ядро:** CPython в WebAssembly (Pyodide) — код выполняется в браузере, сервер не нужен.
- **Оболочка как у эталона:** редактор + условие задачи + скрытые тесты + кнопка «Проверить» + эталонное решение после сдачи.
- **«Приборы» вместо осциллографа:** построчный трейс (что в переменных на каждом шаге), визуализация списков/деревьев, «черепашья графика», мини-игра с отрисовкой на canvas.
- **ИИ-ассистент:** не пишет ответ, а объясняет конкретную ошибку из traceback («строка 7: IndexError — ты берёшь элемент до того, как список заполнен»).
- **Сложность:** S–M. **Эффект:** максимальный — Python есть в программе почти любого IT-квантума.

### 3.2. Терминал Linux / сервер в браузере
- **Ядро:** xterm.js + виртуальная файловая система + набор утилит + «сервисы» (nginx-заглушка, пользователи, права, cron).
- **Задания:** «создай пользователя и запрети ему вход», «найди, кто ест место на диске», «подними сайт на порту 8080», «настрой автозапуск скрипта».
- **Аналог осциллографа:** панель состояния (процессы, порты, права) — видно, что ты изменил в системе.
- **Сложность:** M. **Эффект:** высокий для тем «ОС, сети, системное администрирование» и олимпиад/конкурсов.

### 3.3. Симулятор сети в браузере — «Packet Tracer без установки»
- **Ядро:** канвас с топологией (ПК / коммутатор / маршрутизатор / точка доступа / сервер), реальные IP-маски, ARP, DHCP, DNS, NAT, VLAN, статическая маршрутизация; CLI в стиле Linux/IOS опционально.
- **«Осциллограф» этого продукта:** анимация пакета по шагам — «пакет ушёл, ARP не ответил, вот почему ping не идёт». Это то, чего нет даже в Packet Tracer в наглядном виде.
- **Автопроверка:** не «правильная ли команда», а «достижима ли цель»: проверяем связность/изоляцию VLAN/работу DHCP по чек-листу.
- **Почему ниша свободна:** Packet Tracer тяжёлый, требует установки и аккаунта; существующие браузерные симуляторы (NetSim, pktsim, NetSandbox, netverdict) — англоязычные, платные или не школьные. **Русскоязычного школьного аналога нет.**
- **Сложность:** L (но можно срезать до VLAN+IP+ping = M). **Эффект:** самый «уникальный» продукт из списка.

### 3.4. Веб-студия с проверкой по критериям
- HTML/CSS/JS с мгновенным рендером + проверки не «на память», а по требованиям: адаптивность, семантика, доступность (`aria`, контраст), нет горизонтального скролла на 360px.
- «Прибор» — инспектор: показывает, какие элементы ломают вёрстку.
- **Сложность:** S–M. **Эффект:** высокий — веб в программе есть почти всегда, а дети любят «сразу видно результат».

### 3.5. SQL / данные
- SQLite в браузере (sql.js), готовые датасеты (школа, магазин, город), задачи с автопроверкой по результату запроса, визуализация результата графиком.
- **Сложность:** S. **Эффект:** средний-высокий (темы «базы данных», проекты «данные и аналитика»).

### 3.6. Кибербезопасность: локальные CTF-задания
- Задания, которые решаются в браузере без сервера: разбор HTTP-заголовков, «найди уязвимость в коде», стеганография, хеши, «подбери пароль по словарю», «прочитай чужой cookie».
- Полноценный CTF требует бэкенда — поэтому реалистичный формат: **«разбор инцидента»** на симуляторе плюс мини-игры, а не хакерская песочница.
- **Сложность:** M. **Эффект:** высокий по вовлечённости (соревновательность), но требует методической аккуратности.

### 3.7. «Нейросеть изнутри» / ИИ-грамотность
- Собрать архитектуру мышкой, обучить маленькую сеть на TensorFlow.js (или своём движке) на своих данных, посмотреть, как меняются веса, почему переобучение.
- **Сложность:** M. **Эффект:** высокий «вау», но программа IT-квантума часто не успевает дойти до этого.

### 3.8. Бонус — мостик к эталону
У эталона уже есть **MicroPython на ESP32 / Raspberry Pi Pico**. Это прямой стык Робо- и IT-квантума: один и тот же ребёнок пишет Python в «IT-классе» и запускает его на «железе» в Robx. Такой мостик можно оформить как совместный модуль двух квантумов — самый дешёвый способ получить «свой» аналог, ничего не разрабатывая.

## 4. Приоритеты (если ресурс — один человек и одно лето)

| № | Продукт | Сложность | Эффект | Вердикт |
|---|---|---|---|---|
| 1 | Python-класс с автопроверкой | S–M | ★★★★★ | **Делать первым** |
| 2 | Веб-студия с проверкой по критериям | S–M | ★★★★ | Делать вторым (переиспользует ядро) |
| 3 | Симулятор сети | L / M в урезанном виде | ★★★★★ (уникальность) | Стратегическая ставка |
| 4 | Терминал Linux | M | ★★★★ | Хорош как «модуль 2» к сети |
| 5 | SQL | S | ★★★ | Быстрая победа |
| 6 | CTF-задания | M | ★★★★ вовлечённость | После 1–3 |
| 7 | Нейросети | M | ★★★ | Как «вау-модуль» |

**Рекомендация:** начать с 3.1 (Python) — он даёт работающий продукт за 2–4 недели, закрывает самую частую тему и обкатывает всю инфраструктуру (редактор, автопроверка, аккаунты, облако, ИИ-ассистент). Дальше на этом же ядре добавлять модули: сеть → терминал → веб.

## 5. MVP первой версии (Python-класс), 6–8 недель

**Технологии:** статический фронтенд (без бэкенда для запуска кода) + Pyodide + CodeMirror; бэкенд только для аккаунтов, облака проектов и статистики; локальное сохранение через `localStorage` — чтобы работало и без регистрации.

**Обязательно в MVP:**
1. Экран «Тема → теория в 1 экран → 4–6 задач».
2. Редактор с подсветкой, запуск, вывод, `input()` через поле ввода.
3. Скрытые тесты + кнопка «Проверить» + понятное сообщение об ошибке (ожидалось / получено).
4. Прогресс ученика, «открыть следующую тему после решения всех задач».
5. Облако/ссылка: сохранить проект, поделиться ссылкой на решение (ученик → педагог).
6. ИИ-ассистент: объясняет ошибку, ответ не даёт (промпт-ограничение).
7. Таблица педагога: кто что сдал, где застрял класс (агрегированно, без ручной проверки).

**Контент:** 8–10 тем первого модуля (переменные, условия, циклы, списки, строки, функции, словари, модули, базовые алгоритмы) × 5 задач = 40–50 задач. Это ~2 недели работы методиста, и это узкое место, а не код.

**Метрики успеха:** ребёнок без помощи взрослого решает первую задачу < 3 минут; доля домашних ДЗ, сданных до урока, ≥ 50%; время педагога на проверку −80%.

**Риски:** Pyodide грузится ~5–10 МБ при первом входе (лечится кэшем и оффлайн-режимом); нельзя `pip`-нуть тяжёлые C-расширения (лечится списком поддерживаемых пакетов); школьные фильтры и старые браузеры (нужен тест на Alt Linux и планшетах); контент устаревает быстрее кода (нужна админка).

## 6. Если разработки нет вообще — 12 ходов без программирования

1. Собрать «карту инструментов» квантума: что из существующего бесплатного закрывает какую тему (Pyodide-песочницы, NetSim/pktsim/NetSandbox, sql.js, Colab, Scratch, App Inventor, OverTheWire, JSFiddle/CodePen).
2. Единая точка входа: одна страница с QR-кодами на все среды по темам — уже снимает половину боли урока.
3. Свои карточки заданий с критериями проверки (вместо «сделай проект»).
4. Автопроверка через тесты в существующей LMS/Google-формах + скрытые тесты в коде.
5. Шаблоны проектов-заготовок в репозитории квантума.
6. Свой `llms.txt` и FAQ-страница — чтобы вас находили нейросети (эталон именно так и растёт).
7. Мини-хакатоны внутри квантума на чужой платформе.
8. Мостик с Robx/MicroPython: Python-код запускается на «железе» Робо-квантума.
9. Договориться о «песочнице без прав администратора» — портативные сборки, веб-версии.
10. Записывать 3-минутные видео «как поднять среду» и выдавать их вместо объяснения на уроке.
11. Собрать лучшие ученические работы в публичное портфолио-сайт квантума.
12. Завести GitHub-организацию квантума: код детей живёт в репозиториях, а не в папках на школьном ПК.

## 7. Что дети могут сделать сами по аналогии (готовые квантум-проекты)

Это отдельная ценность: каждый пункт — годный проект на 2–3 месяца с защитой.

1. **Мини-симулятор «Светофор»** — своя песочница с canvas и проверкой решений младших групп.
2. **Тренажёр по маскам подсетей** — генератор задач + проверка + объяснение ошибки.
3. **Бот-помощник квантума** — отвечает на вопросы про расписание и оборудование.
4. **Сайт-портфолио квантума** с автоматической подгрузкой проектов из GitHub.
5. **Визуализатор алгоритмов сортировки** с пошаговым трейсом (аналог «осциллографа»).
6. **Симулятор «пароль и хеши»** — наглядно, почему важна длина и соль.
7. **Свой мини-эмулятор платы** на JavaScript для младших (кнопка → светодиод).
8. **Генератор вариантов контрольных** с автопроверкой (для педагога).

## 8. Чего не делать

- **Не делать «ещё один курс с видео».** Эталон силён средой, а не контентом.
- **Не начинать с сети или нейросетей.** Дорого, долго, нет инфраструктуры автопроверки.
- **Не требовать регистрации до первого результата.** Это убивает вход.
- **Не запирать код на сервере,** если можно исполнить в браузере: дешевле, приватнее, работает при плохом интернете.
- **Не делать всё сразу «для всех квантумов».** Один предмет, один цикл, доведённый до конца.

---

### Резюме в одну строку
В IT-квантуме нужно строить не сайт, а **браузерный тренажёр среды с автопроверкой и визуализацией того, что обычно невидимо**; начинать с Python-класса (S–M), затем сеть и терминал, а мостик к MicroPython/ESP32 использовать как бесплатную синергию с Робо-квантумом.
