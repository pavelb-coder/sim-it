# mod_simquantum — «Тренажёр IT-квантума» для Moodle

Элемент курса, который встраивает в Moodle браузерный тренажёр линейки IT-квантума:
ученик остаётся в курсе, тренажёр открывается прямо на странице элемента курса.

Внутри — 8 тренажёров с задачами и автопроверкой (Python-класс, C++-класс, терминал Linux,
симулятор сети, веб-студия, SQL, кибербезопасность, нейросети) и 2 свободные песочницы кода
(Python и C++). Всего **583 задачи**.

Всё работает **офлайн**: файлы тренажёров лежат внутри плагина и отдаются самим Moodle —
интернет на машине ученика не нужен, ничего устанавливать не надо, никаких внешних CDN.

- Плагин: `mod_simquantum`, версия 1.0.0
- Moodle: 4.0 … 5.x, PHP 8.0+
- Лицензия: GPL-3.0-or-later (как у Moodle)
- Ветка `moodle-plugin` — только плагин; исходники тренажёров живут в `main`

---

## Что умеет

| Возможность | Как это выглядит в курсе |
|---|---|
| Элемент курса | Преподаватель добавляет «Тренажёр IT-квантума», выбирает площадку из списка |
| Описание | Своё название и описание над тренажёром — как у любого элемента курса |
| Высота области | Настраивается (400…3000 px), на телефоне рамка подстраивается под ширину |
| Полный экран | Ссылка «Открыть тренажёр на всю страницу» — та же страница без обвязки курса |
| Права | `mod/simquantum:addinstance` (создавать) и `mod/simquantum:view` (проходить) |
| Резервные копии | Настройки элемента курса попадают в бэкап и восстанавливаются |
| Отчёты | Событие «Тренажёр IT-квантума просмотрен» в логах и отчётах активности |
| Настройка сайта | Администратор выбирает, какие тренажёры доступны преподавателям |

Чего плагин сознательно **не** делает: не ставит оценки и не отмечает завершение. Прогресс
ученика живёт в его браузере (`localStorage`), в Moodle уходят только стандартные записи о
просмотре. Это честное «встраивание» — журнал оценок остаётся за преподавателем.

## Установка

### Способ 1. Загрузка ZIP (проще всего)

1. Скачайте [`dist/mod_simquantum.zip`](dist/mod_simquantum.zip) из этой ветки.
2. Moodle → **Администрирование сайта → Плагины → Установить плагины → Установить плагин из ZIP-файла**.
3. Загрузите архив, тип «Элемент курса (mod)» определится сам, нажмите «Установить плагин».
4. **Администрирование сайта → Уведомления** — Moodle создаст таблицу `simquantum`.
5. В курсе: **Добавить элемент или ресурс → Тренажёр IT-квантума**.

### Способ 2. Копированием папки

```bash
git clone --branch moodle-plugin https://github.com/pavelb-coder/sim-it.git simquantum-plugin
cp -a simquantum-plugin/simquantum /path/to/moodle/mod/simquantum
```

Затем в Moodle: **Администрирование сайта → Уведомления**. Права на папку —
как у остальных плагинов (`www-data:www-data`, файлы 0644, папки 0755).

### Способ 3. Git-подмодуль (для сопровождения)

```bash
cd /path/to/moodle/mod
git submodule add --branch moodle-plugin https://github.com/pavelb-coder/sim-it.git simquantum-src
ln -s simquantum-src/simquantum simquantum
```

## Как добавить тренажёр в курс

1. Включите редактирование курса → **Добавить элемент или ресурс** → **Тренажёр IT-квантума**.
2. Название (например «Python: модуль 3»), при желании — описание.
3. Выберите тренажёр. В подписи видно, сколько в нём задач:
   `Python-класс — 239 задач с автопроверкой`, `Python-песочница — свободный код, без задач`.
4. Задайте высоту рабочей области (по умолчанию 900 px; для песочниц удобно 1000–1200).
5. Сохраните. Ученик видит страницу с описанием и тренажёром — задачи решаются тут же.

Тренажёр внутри рамки полностью функционален: свой редактор кода, автопроверка, подсказки,
переключение задач, «Открыть все задачи» для режима педагога.

## Настройки сайта

**Администрирование сайта → Плагины → Элементы курса → Тренажёр IT-квантума**

* **Тренажёры, доступные преподавателям** — снимите галочки с тех, что не нужны
  (например, оставьте только Python и C++). Отключённые не появятся в списке выбора.
* Там же — памятка о том, что файлы тренажёров лежат в `assets/` плагина.

├── view.php               страница элемента курса: описание + рамка с тренажёром
├── content.php            отдаёт автономный HTML тренажёра (только из assets/)
├── index.php              список тренажёров курса
├── settings.php           настройки сайта
├── styles.css             оформление рамки
├── classes/local/catalog.php          каталог тренажёров: код → файл, высота, значения по умолчанию
├── classes/event/course_module_viewed.php
├── classes/privacy/provider.php       данных не хранит (null provider)

### Почему файлы тренажёров лежат внутри

Тренажёры собираются в **один автономный HTML-файл** каждый: движок, стили, задачи и
шрифты уже внутри, внешних запросов нет. Поэтому плагину достаточно отдать один документ —
`content.php` читает файл из `assets/` и отдаёт байт-в-байт. Ни `pluginfile.php`, ни
хранилище файлов Moodle не нужны, а код тренажёра не может быть подменён параметром запроса:
путь берётся только из каталога по коду, сохранённому в настройках элемента курса.

| Тренажёр | Код | Задач | Файл |
|---|---|---|---|
| Python-класс | `python` | 239 | 478 КБ |
| C++-класс | `cpp` | 211 | 461 КБ |
| Терминал Linux | `terminal` | 25 | 91 КБ |
| Симулятор сети | `network` | 22 | 92 КБ |
| Веб-студия | `web` | 22 | 75 КБ |
| SQL-тренажёр | `sql` | 28 | 71 КБ |
| Кибербезопасность | `security` | 21 | 70 КБ |
| Нейросеть изнутри | `ai` | 15 | 65 КБ |
| Python-песочница | `pyplay` | — | 109 КБ |
| C++-песочница | `cppplay` | — | 92 КБ |

## Обновление тренажёров

Файлы в `assets/` — сборка из ветки `main` этого же репозитория.

```bash
# 1. обновить и собрать тренажёры
cd sim-it && git checkout main && git pull
python3 build_site.py

# 2. переложить собранные файлы в плагин
cd /path/to/simquantum-plugin
python3 tools/bundle_assets.py /path/to/sim-it     # по умолчанию ищет ../sim-it

# 3. поднять версию в simquantum/version.php (например 2026111401),
#    пересобрать архив и закоммитить
bash tools/pack.sh
```

В Moodle после обновления файлов: **Администрирование сайта → Разработка → Очистить кеши**.
Версию поднимать обязательно, если меняется только содержимое `assets/` — иначе Moodle не
предложит обновление (кеш браузера сбрасывается параметром версии в ссылке).

## Проверки без установки Moodle

```bash
python3 tools/check_plugin.py            # 36 проверок: синтаксис PHP, язык, каталог, XMLDB, права
php tests/harness/run.php                # 35 проверок: каталог, lib.php, content.php по HTTP
python3 tests/browser/check_framed.py    # браузер: тренажёр работает внутри iframe
```

* `check_plugin.py` — целостность: все `get_string` переведены на en и ru, у каждого
  тренажёра есть файл и подписи, поля `install.xml` совпадают с тем, что пишет код,
  права описаны, в PHP нет BOM и закрывающего `?>`.
* `tests/harness/run.php` — поднимает «мини-Moodle» с заглушкой `config.php`, проверяет
  каталог (включая попытку подстановки `../../config.php`), `add/update/delete_instance`,
  нормализацию кода и высоты, а затем по HTTP — что `content.php` отдаёт **ровно** байты
  файла, отдаёт 404 на неизвестный код и не отдаёт содержимое без права просмотра.
* `tests/browser/check_framed.py` — Chromium: тренажёр Python-класса открывается в рамке,
  видны все 239 задач, код исполняется (`print(2 + 2)` → `4`), песочница считает с вводом,
  заголовок `X-Frame-Options: SAMEORIGIN` на месте, ошибок JS нет.

## Отличия от «просто ссылки на сайт»

* Moodle не пускает посторонние домены в рамку — здесь всё отдаёт сам сайт, поэтому рамка
  работает и в закрытой сети без интернета.
* Прогресс и код ученика сохраняются в браузере, привязанные к домену школы; одна и та же
  площадка в разных курсах делит прогресс — так задумано (это тот же тренажёр).
* Удаление элемента курса не стирает прогресс ученика — он остаётся в браузере.

## Что можно добавить дальше

* Оценка за прогресс: тренажёр уже умеет сообщать число решённых задач через `postMessage`,
  остаётся связать с `grade_item` и `completion` (нужен новый пункт в `mod_form.php`).
* Тип вопроса `qtype_simquantum`: переносить отдельные задачи банка в тесты Moodle.
* Отчёт для учителя: сколько задач решено, по каким темам — потребует хранения прогресса
  на сервере и, значит, описания данных в `classes/privacy/provider.php`.
